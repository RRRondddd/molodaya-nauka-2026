# Локальные учебные заявки

Реальная регистрация, backend и Google Sheets в этой версии не используются.
Ранее подготовленные серверные прототипы удалены как не относящиеся к сценарию РГР.

## Архитектура

`ApplicationForm.jsx` → `application.js` → localStorage → `ApplicationsPanel.jsx`.
Ключ: `young-science-applications-v1`, объект `{version:1, applications:[...]}`.
Запись содержит UUID, ISO дату и время, ФИО, email, ID преподавателя, ID секции,
тему и статус. Список преподавателей — отдельно в `application-config.js`.

Уведомление `applications-changed` обновляет список в текущей вкладке; событие
`storage` обновляет другие вкладки этого же origin. При сохранении читается
актуальный список. Это не транзакционная БД: одновременные изменения в нескольких
вкладках могут перезаписать друг друга. Для демонстрации использовать одну вкладку.

Перед записью валидируются пять полей, проверяются разрешённые преподаватели,
секции, длины, email. Полное совпадение email+преподаватель+секция+тема
(без учёта регистра темы и email) блокирует повтор. Сначала записывается localStorage,
затем показывается подтверждение, очищаются поля и обновляется таблица.
При ошибке записи поля сохраняются, успех не показывается. Повреждённое хранилище
не перезаписывается автоматически; можно явно удалить локальные заявки кнопкой
с подтверждением. Лимит учебного хранилища — 1000 записей, дополнительно действуют
квоты браузера. UUID — технический уникальный номер, а не серверный номер регистрации.

## Статусы и представление

Новая → На рассмотрении / Согласована / Отклонена. Для учебной демонстрации можно
свободно выбирать любой из четырёх статусов. Изменения сохраняются по ID заявки.
Выбор преподавателя фильтрует список, но не ограничивает доступ. На мобильных
таблица отображается карточками с подписями полей. Даты показываются в часовом
поясе устройства; даты программы конференции остаются без изменения.

## Ограничения

Только вымышленные сведения. Нет авторизации, разграничения доступа, шифрования,
синхронизации между устройствами или отправки преподавателям. Любой пользователь
того же браузерного профиля на этом origin может прочитать и изменить записи.
Удаление данных сайта или приватный режим могут удалить заявки. Не сохранять
реальные персональные данные. Данные не отправляются с формы по сети, не попадают
в репозиторий и не передаются помощнику. Внешние шрифты загружаются отдельно и
не получают содержимое заявок. Кнопка удаления очищает только ключ этой системы,
а не весь localStorage origin. После демонстрации рекомендуется удалить записи.

## Сценарий для защиты РГР

1. Ввести «Тестовый Студент Пример», student@example.test, выбрать Теренину Н. Л.,
   первую секцию, тему «Тестовое исследование цифровых медиа».
2. Нажать «Отправить заявку» — появится «Заявка сохранена!».
3. Открыть отдельную страницу `manage.html` («Заявки преподавателей») — запись видна у Теренины, у Харламовой её нет.
4. Выбрать статус «Согласована», обновить страницу — запись и статус остаются.
5. Повторить такую же заявку — будет ошибка дублирования, второй строки не будет.
6. Удалить тестовые записи через кнопку с подтверждением.

Автоматизация этого сценария: `npm run test:form` при запущенном preview.
Используются только синтетические данные и изолированные браузерные контексты.

Главная страница не содержит таблиц и ссылки на управление; прямой адрес не является секретом или ограничением доступа.
