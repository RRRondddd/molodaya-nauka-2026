# Предварительные заявки: проект интеграции

## Что работает сейчас

В production-конфигурации `src/application-config.js` установлен demo=true,
approved=false, endpoint пустой. Форма проверяет поля в браузере и не вызывает
сетевую отправку, ничего не пишет в Sheets, localStorage или URL. Для проверки
используйте только вымышленные данные. Окно получения заявки в деморежиме не
открывается. Список руководителей содержит шесть преподавателей из программы по указанию пользователя. Полные имена не добавлялись: сохранены опубликованные в задании инициалы.
Существующая регистрация через преподавателей и её сроки остаются в силе.

`server/Code.gs` — исходник обработчика, пока НЕ развёрнутый и НЕ проверенный
на реальных Google Sheets. Скрипт выключен по умолчанию. Запуск после согласования
оператором персональных данных и организаторами конференции.

## Поток данных

React → HTTPS gateway → Google Apps Script → отдельная закрытая таблица руководителя.

GitHub Pages обслуживает только статические файлы. Для production необходим
отдельный серверный gateway (можно на доступном бесплатном тарифе с учётом квот).
Это обязательный компонент перед запуском. Нельзя заменять его no-cors fetch,
JSONP, отправкой через iframe или трактовать opaque-ответ как успех.
Apps Script ContentService перенаправляет ответ на googleusercontent.com;
браузерный CORS и preflight нельзя считать настроенными автоматически.
Gateway выполняет серверный запрос с переходами по редиректам и возвращает
браузеру проверяемый JSON с разрешённым CORS только для origin сайта.
Origin — дополнительная проверка, не аутентификация.

Публичный клиент передаёт только name, email, supervisorId, sectionId, topic,
consent, consentVersion и requestId. Sheet ID, секрет gateway, HMAC pepper и
сервисные учётные данные никогда не передаются в браузер или VITE_*.
Значения конфигурации Google хранить только в Script Properties и секретах gateway.
Не публиковать экспорт реальных заявок, логи запросов или ответы с персональными данными.

## Подготовка Google

1. Согласовать оператора, основания, цели сбора, состав полей, текст и версию
   согласия, сроки хранения/удаления, отзыв согласия и доступ субъектов.
   Проверить применимость требований к локализации и трансграничной передаче
   данных с ответственным учреждения. Демотекст чекбокса не является юридическим согласием.
2. Получить утверждённый список руководителей. Изменить отдельно клиентский
   список `supervisors` и серверный список маршрутов, с одинаковыми внутренними ID.
   Руководители секций из программы автоматически в список не включаются.
3. Для каждого руководителя создать отдельную таблицу от учётной записи оператора.
   General access: Restricted. Доступ через Drive только этому руководителю и
   уполномоченным администраторам. Отключить публикацию в интернете и доступ по ссылке.
   Фильтры общей таблицы не обеспечивают изоляцию. Право редактора даёт изменение
   данных: при необходимости назначать просмотр и вести рассмотрение отдельно.
4. На листе `Applications` каждой таблицы создать единственную строку заголовков:
   requestId, receiptId, payloadHash, fingerprint, createdAt, name, email,
   supervisorId, sectionId, topic, consentVersion (именно этот порядок).
   Ограничить редактирование технических столбцов и запускать одну версию скрипта.
5. Создать отдельную административную закрытую таблицу с листом `RateLimits`:
   emailHash, timestamp. Руководителям к ней доступа не давать. Это не общая
   таблица заявок; содержит только псевдонимизированные счётчики попыток.
6. Создать Apps Script V8 проект, скопировать `server/Code.gs`.
   Script Properties (значения не в репозитории):
   - COLLECTION_APPROVED: `false` до завершения всех проверок;
   - SUPERVISOR_ROUTES: JSON `{ "internal-id": { "spreadsheetId": "PRIVATE_ID" } }`;
   - CONSENT_VERSION: утверждённый номер версии;
   - HASH_PEPPER: случайный длинный секрет для HMAC;
   - GATEWAY_SECRET: отдельный случайный секрет;
   - RATE_LEDGER_ID: ID административной таблицы.
7. Развернуть Web app от имени оператора. Доступ для серверного gateway выбрать
   в соответствии с политиками Workspace. Если endpoint доступен анонимно,
   GATEWAY_SECRET обязателен. Не публиковать URL и секрет в клиенте. Авторизация
   скрипта даёт ему доступ к таблицам оператора — не использовать личный аккаунт.

## Обязательный контракт gateway (реализация требуется перед запуском)

Принимать только POST JSON, максимум 12 KB; разрешить известные поля и отбросить
любые дополнительные поля (включая переданный клиентом gatewaySecret).
Ограничить размеры и провалидировать схему, затем добавить собственный секрет
GATEWAY_SECRET из серверного хранилища. URL Apps Script — серверная настройка.

Настроить ограничение частоты по IP на доверенном ingress (не доверять произвольному
X-Forwarded-For), общий лимит и при необходимости проверяемую сервером CAPTCHA.
Рекомендуемый начальный лимит: 5 попыток / 10 минут на IP, с настройкой для общей
сети университета. Apps Script дополнительно ограничивает попытки по HMAC email:
5 / 10 минут. CacheService — ускоритель, основной счётчик — закрытый RateLimits.
Скрипт не знает IP посетителя; одна проверка email не защищает от ботов и смены email.
Прямые запросы без серверного секрета отвергаются, но могут расходовать квоту
скрипта. Для серьёзной нагрузки нужен более подходящий backend.

Не логировать тела, email и имена. Сопоставлять коды INVALID→400,
UNAUTHORIZED→403, DUPLICATE/IDEMPOTENCY_CONFLICT→409, RATE_LIMIT→429,
DISABLED→503, BUSY/SERVER_ERROR/UNCONFIRMED→503. Apps Script возвращает JSON-коды,
поэтому его HTTP 200 само по себе не успех. Для подтверждённой записи gateway
возвращает HTTP 200 и только `{ok:true,status:"saved",requestId,receiptId}`.
Никогда не подменять сетевую ошибку успехом. Прокси не должен повторять запрос
с новым requestId при таймауте.

## Дубликаты, ошибки и ограничения

Один ScriptLock защищает проверку и запись во всех маршрутах. requestId защищает
повтор запроса после таймаута. Другой payload с тем же ID — конфликт. Одинаковые
email+руководитель+секция+тема с новым ID — DUPLICATE без сообщения об успехе.
Это не запрет разных заявок на разные темы: соответствующее правило должен
утвердить организатор. После ошибки поля и ID остаются в памяти страницы;
изменённые данные после неопределённого исхода требуют уточнить статус у оператора.
При перезагрузке ID теряется, но fingerprint продолжает защищать от дубликата.
Данные и ID намеренно не сохраняются на устройстве.

Скрипт очищает формулы из пользовательских ячеек, проверяет запись через flush
и повторное чтение. Сбой после фактической записи может дать ошибку, повтор с
тем же ID безопасен. Sheets не транзакционная БД, строки нельзя редактировать
одновременно вручную с техническими полями. Сканирование строк имеет линейную
стоимость; при росте объёма требуется БД/индекс. Старые записи RateLimits удалять
по утверждённой политике (например, ежедневным триггером старше суток), заявки —
по согласованному сроку. HMAC записи тоже защищать и удалять, не считать анонимными.

## Чек-лист включения

На отдельных тестовых таблицах с синтетическими данными проверить:
- два руководителя → две разные таблицы, ни одного ID таблиц в DevTools;
- доступ Google-аккаунта руководителя A запрещён к таблице B;
- невалидные поля, чужой supervisorId, неподтверждённая версия согласия отвергаются;
- повтор requestId не добавляет строку; изменённый payload даёт конфликт;
- одинаковая заявка с другим ID не дублируется; параллельные запросы не дублируются;
- шестая попытка ограничена; ограничение gateway и неправильный секрет работают;
- отзыв прав на таблицу, квота, ошибка сети и таймаут не открывают окно успеха;
- только реально записанная строка даёт совпадающие receiptId и requestId;
- имя или тема `=IMPORTXML(...)` остаются текстом;
- CORS проверен с реального GitHub Pages origin, запросы не пишутся в логи.

После утверждения проверить список и маршруты преподавателей, заменить демотекст согласия на согласованный
документ и пояснения режима; выставить endpoint gateway, consentVersion,
approved=true и demo=false. Настройки клиента публичны, секретов здесь быть не
должно. В Script Properties включить COLLECTION_APPROVED=true только после
проверки маршрутов и прав. Модальное окно в интерфейсе открывается исключительно
после подтверждённого ответа. Оно означает запись в таблицу с доступом выбранного
руководителя; отправка email-уведомлений этой реализацией не предусмотрена.
