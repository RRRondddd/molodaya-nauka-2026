# Молодая наука — 2026

Адаптивный лендинг научно-практической конференции имени А. В. Новикова, НГУЭУ. **Учебный проект. Неофициальный сайт конференции.**

React 19, Vite 7, обычный CSS. Сервер приложения, база данных, ключи API и платные сервисы не нужны. Иллюстрация создана CSS, фотографии не используются. Шрифт Manrope загружается из Google Fonts; при недоступности используется системный Arial.

## Локальный запуск

Нужен Node.js 24 LTS и npm.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, с путём `/molodaya-nauka-2026/` (обычно порт 5173).

```bash
npm run build
npm run preview
```

Сборка находится в `dist/`. Preview позволяет проверить готовую сборку (обычно порт 4173). Не открывайте `dist/index.html` напрямую как файл.

## GitHub Pages

1. Отправьте файлы в ветку `main` репозитория `RRRondddd/molodaya-nauka-2026`.
2. В GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. В **Actions** дождитесь успешного workflow `Deploy to GitHub Pages`. Его также можно запустить вручную через **Run workflow**.
4. Адрес после успешной публикации: `https://rrrondddd.github.io/molodaya-nauka-2026/`.

Workflow `.github/workflows/deploy.yml` выполняет `npm ci`, сборку и публикацию `dist`. Путь `/molodaya-nauka-2026/` настроен в `vite.config.js`; при переименовании репозитория измените `base`. Публикация требует доступных GitHub Actions и Pages в настройках репозитория. Из среды разработки публикация не выполнялась.

## Где менять информацию

- `src/main.jsx` — все тексты, подсказки `prompts` и компоненты; `src/conference.js` — секции и FAQ; `src/assistant.js` — правила ответов и подбора секций.
- `src/styles.css` — оформление, мобильные размеры, анимация и режим уменьшенного движения.
- `index.html` — название вкладки и метаданные.
- `vite.config.js` — путь публикации.

Помощник — локальная система рекомендаций секций и справочных ответов по ключевым словам, без генеративной модели и внешнего API. Он не регистрирует участников, не сохраняет переписку после перезагрузки и может не распознать переформулированный вопрос. Неизвестные сведения предлагает уточнять у преподавателя.

## Локальный подбор секций

Помощник — локальная система рекомендаций, без генеративной ИИ-модели,
платных API и передачи вопросов внешнему сервису. Сначала он проверяет
справочные намерения (регистрация, программа, требования, место), затем
подбирает направление по тексту исследования.

Алгоритм в `src/assistant.js` приводит текст к нижнему регистру, заменяет `ё`
на `е`, разделяет слова и ищет основы слов, короткие сокращения и фразы.
Поддерживаются, например, «пиар»/PR, «нейросети»/ИИ/AI, «соцсети»/«социальные
сети», «стартап»/startup. Короткие сокращения проверяются как целые слова.
Каждая группа понятий даёт один балл своей секции независимо от повторений.
Если два лучших результата отличаются не более чем на один балл, помощник
перечисляет подходящие направления и просит уточнить фокус. При отсутствии
совпадений он не назначает секцию случайным образом. В рекомендации объясняется,
какие направления найдены, и предлагается согласовать выбор с руководителем.

Это словарные правила, а не понимание смысла: опечатки, отрицания, сложные
формулировки и темы вне словаря могут обрабатываться неверно. Баллы не являются
вероятностями. Для уточнения напишите основной предмет исследования новым
сообщением: контекст предыдущего вопроса автоматически не объединяется.
Названия, даты и руководители берутся из общего `src/conference.js`, который
также использует сайт. FAQ и программа сохранены без изменения содержания.

Проверки алгоритма (встроенный Node.js test runner, без новых зависимостей):

```bash
npm test
npm run build
```

Тесты находятся в `tests/assistant.test.js`: три секции, синонимы,
междисциплинарные и неизвестные темы, повторения слов и справочные ответы.


## Проверка мобильного интерфейса

Автоматическая проверка Playwright проверяет production-сборку на ширине
320, 375 и 768 px: открытие/закрытие меню, навигацию, секции, ответы чата,
неоднозначные и неизвестные темы, сообщение длиной 500 символов, отсутствие
горизонтального переполнения и ошибок JavaScript. Для чата дополнительно
проверяются вертикальные границы на высоте 568 и 440 px и закрытие Escape.

```bash
npm ci
npx playwright install chromium
npm test
npm run build
npm run preview -- --port 4175
# В другом терминале:
npm run test:mobile
```

При наличии системного Chromium загрузка браузера не нужна:
`CHROMIUM_PATH=/usr/bin/chromium npm run test:mobile`.
Другой адрес сборки можно задать через переменную `TEST_URL`.
Браузерные проверки запускаются отдельно; workflow Pages автоматически
выполняет алгоритмические тесты и production-сборку перед публикацией.


## Демонстрационная форма предварительной заявки

В разделе «Участие» добавлена форма с валидацией ФИО, email, руководителя,
секции, темы и чекбокса. Сейчас это только проверка интерфейса: реальные данные
не вводить, сеть не вызывается, заявка не создаётся и окно успеха не открывается.
Демонстрационный список отдельно в `src/application-config.js`. Конфигурация
заблокирована (`demo: true`, `approved: false`, пустой endpoint).

- `src/ApplicationForm.jsx` — интерфейс, ошибки, фокус, диалог подтверждения.
- `src/application.js` — валидация и строгий контракт подтверждения сервером.
- `server/Code.gs` — неразвёрнутый Google Apps Script: маршрутизация по разрешённым
  внутренним ID, проверка данных, согласия, секрет gateway, лимит, блокировка,
  защита от повторов и формул, проверка сохранения.
- [Развёртывание и безопасное включение](docs/applications.md) — отдельные закрытые
  таблицы, права Drive, обязательный gateway, настройки, ограничения и чек-лист.

Ни Google-ресурсы, ни gateway автоматически не создавались. Не добавлять Sheet ID,
секреты или реальные персональные данные в репозиторий. Модульные серверные тесты
используют заглушки сервисов Google, а не настоящие Sheets. Для запуска необходимы
утверждённые руководители, правила обработки данных, инфраструктура и проверка
реальной интеграции по инструкции; текущий деморежим не является регистрацией.

Проверка формы в браузере (при запущенном preview на 4175):

```bash
CHROMIUM_PATH=/usr/bin/chromium npm run test:form
```

При установленном Playwright Chromium можно опустить CHROMIUM_PATH. Скрипт
проверяет 320/375/768/1440 px, обязательные поля, email, согласие, клавиатуру,
границы элементов, отсутствие POST и ложного успеха. `npm test` дополнительно
проверяет серверный исходник на заглушках: маршруты, повторы, лимиты и ошибки.
